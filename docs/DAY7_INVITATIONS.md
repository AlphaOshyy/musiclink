# Day 7. Blind review, shortlist and invitations

New authenticated routes: GET /api/projects/:id/shortlist for project owner, DELETE /api/projects/:id/shortlist/:candidateId to remove a creator without active pending or accepted invitation, and GET /api/me/sent-invitations for invitation status tracking. Invitation send requires project ownership, open project status, a shortlisted existing creator, and no prior invitation for the same creator/project. Duplicate sends return 409. Receiver response accepts accepted or declined once only, using an atomic conditional update so repeat changes return 409. Existing client requests and authentication flows remain. The MusicLink interface adds owner shortlist management, invitation status, sent/received tabs. Privacy scope: only owner reads shortlist, only sender reads their sent invitations, only receiver reads and answers received invitations. Existing blind-review matching remains in use. Production UI and database behavior require live verification after deployment.
